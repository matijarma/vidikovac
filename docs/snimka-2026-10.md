# Snimka (October 2026): three days without trams, replayed

*Brief for the page `/snimka/`, written 1 October 2026 from the owner's decisions of that day. Execution prompts and evidence live in the owner's working folder `review.local/snimka/` (not published). Production at the time of writing: `62e8c129` on `main`.*

## 0. How to read this brief

§2 holds the decisions. §3 says what was recorded. §4 names the lanes and the one deploy. §5 is the data contract, binding for every lane, verbatim. §6 is the offline pipeline, §7 the worker route, §8 the page. §9 lists the rules for agents, §10 the acceptance rows, §11 every Croatian string of the page, verbatim. §12 is what this pass does not build. Where a lane prompt is more specific than this brief it wins on specifics; on a decision this brief wins.

## 1. Why this page

From Monday 28 to Wednesday 30 September 2026 the workers of ZET and Zagrebački holding were on strike. Every source of Kaj ima? kept answering, and the city it described did not exist: the fleet fell from 172 vehicles to between 0 and 6 for 66 hours, BAJS bikes drained from 1,866 to 534, ZET's realtime feed went empty and froze twice, the Županijski sud u Zagrebu ruled both strikes illegal on Wednesday, and the fleet came back from 2 to 151 vehicles in 65 minutes that evening. The product itself changed its voice in the middle of it: the October upgrade, which gives the product an expectation of the fleet and a service state, went live on Tuesday at 22:41 and 22:55.

Everything was recorded: ZET's frames every 10 seconds, the product's published state every minute, the 200 BAJS stations every minute, the City's closures, ZET's notices, the press, the weather, and the public screen itself in ten-minute observations with captures. The page replays those three days on one clock. It is the showcase of the thesis in [When the city stops matching the model](unexpected-city-2026-09-27.md): a companion has to know the state of the city, not only the health of its sources.

It is a recording, replayed with the product's own engine. It is not a simulation: that word belongs to the synthetic test corridor of the motion model, and nothing on the page is invented.

## 5. The data contract (binding)

`shared/snimka.ts` (types, constants, validators) and `shared/snimka-codec.ts` (encoders and decoders) are DOM-free and import nothing outside `shared/`. The pipeline writes these shapes, the route serves them unchanged, the page reads them.

Rules:
- Every time column is a fixed-length array from `t0` by `step`. **Missing is `null`, never 0.** Zero is a count observed as zero (a frame with no vehicles is a real 0).
- All times are integer epoch seconds; coordinates are `[lon, lat]`.
- Every object except `manifest.json` is content-named `<name>.<sha256 first 16 hex>.<ext>` and immutable; manifest paths are relative to `/api/snimka/v1/`.

```ts
export const SNIMKA_VERSION = 1;
export const SNIMKA_API = '/api/snimka/v1/';
export const SNIMKA_WINDOW = { fromSec: 1790532000, toSec: 1790748000, minutes: 3600 } as const;     // Sun 27 Sep 20:00 to Thu 1 Oct 08:00 Zagreb
export const SNIMKA_COMPARISON = { day: '2026-09-24', fromSec: 1790200800, minutes: 1440 } as const; // Thu 24 Sep 00:00 Zagreb
export const ZAGREB_OFFSET_S = 7200;                     // CEST for the whole window and the comparison day
export const MOTION_STEP_S = 10, MOTION_CHUNK_S = 600, MOTION_TICKS = 60, BAJS_STEP_S = 300;
export const SPEEDS = [1, 60, 600, 3600] as const;       // replay seconds per wall second
export type Speed = (typeof SPEEDS)[number];
export type SnimkaState = 'normal' | 'reduced' | 'silent' | 'unknown';
export type Col<T> = (T | null)[];

export interface HashedRef { path: string; bytes: number; sha256: string }
export interface NetworkRef extends HashedRef { feedVersion: string; graphHash: string; paths: number; shapes: number }
export interface Attribution { id: 'zet' | 'zet-rss' | 'nextbike' | 'zagreb-closures' | 'dhmz' | 'news' | 'osm' | 'kajima'; text: string; url: string | null; licence: string; adaptation: string | null }

export interface SnimkaManifest {
  version: 1; builtAt: string; title: string;
  build: { commit: string; inputs: Record<string, string> };       // input fingerprint per stage
  window: typeof SNIMKA_WINDOW & { tz: 'Europe/Zagreb'; utcOffsetMin: 120 };
  comparison: typeof SNIMKA_COMPARISON;
  serviceLiveFromSec: number;                                      // first minute with a non-null published.service
  networks: { '395': NetworkRef; '396': NetworkRef };              // frozen byte copies of zet-network.json (feeds 000395 and 000396)
  files: { series: HashedRef; comparisonSeries: HashedRef; motionIndex: HashedRef; stations: HashedRef; bajs: HashedRef;
           closures: HashedRef; events: HashedRef; notices: HashedRef; news: HashedRef; screenIndex: HashedRef; board106: HashedRef;
           grid: HashedRef | null };                               // grid is null in v1
  attribution: Attribution[];
  notes: string[];                                                 // Croatian footnotes (gaps and caveats)
}

export interface SeriesFile {
  v: 1; t0: number; step: 60; n: number;                           // 3600 for the window, 1440 for the comparison day
  seen:     { all: Col<number>; tram: Col<number>; bus: Col<number> };       // the current twin replayed over the frames: fleetSeen at the minute's last frame; null = no frame in the minute
  expected: { all: Col<number>; tram: Col<number>; bus: Col<number> };       // expectationAt per minute (merged 000396 and 000395 calendars); null only where no calendar knows the date
  service:  { state: Col<SnimkaState>; since: Col<number>; ratio: Col<number>; hold: Col<'stale' | 'below-min' | 'no-calendar' | 'gap'> };  // replayed state machine; 'gap' = no frame in the minute, state carried
  feed:     { headerAgeS: Col<number>; entities: Col<number>; rejectedFuture: Col<number>; hiddenDepot: Col<number>; hiddenParked: Col<number> };
  published: { vehicles: Col<number>; itemCount: Col<number>; status: Col<'live' | 'stale' | 'down'>; service: Col<SnimkaState> } | null;   // what production said (teaser.jsonl); null for the comparison day
  bikes:    { total: Col<number>; empty: Col<number>; reporting: Col<number> } | null;    // null for the comparison day
  closures: { active: Col<number>; version: Col<number> } | null;                       // null for the comparison day
  hourly:   { t0: number; n: number; tempC: Col<number>; weather: Col<string>; newsPulse: number[] | null };  // DHMZ Zagreb-Maksimir; newsPulse = relevant press items per hour after de-duplication (not the curated list); null for the comparison day
}

export interface MotionSegment { k: number; on: 0 | 1 | 2; idx: number; v: number[] }
// k = first tick of the segment (0..59); on 0 = metres along net.paths[idx], on 1 = metres along net.shapes[idx], on 2 = free (idx -1)
// v for on 0/1: [s0, ds1, ds2, ...] integer metres, delta-encoded; for on 2: [lon0, lat0, dlon1, dlat1, ...] in 1e-5 degrees, delta-encoded
export interface MotionVehicle { id: string; route: string | null; label: string | null; kind: 0 | 3 | null; segs: MotionSegment[] }   // kind = GTFS route_type; label = the route's short name; a new segment at every gap or geometry change
export interface MotionChunk { v: 1; net: '395' | '396'; t0: number; step: 10; n: 60; vehicles: MotionVehicle[] }
export interface MotionIndex { v: 1; step: 10; chunkSec: 600; chunks: { path: string; sha256: string; bytes: number; net: '395' | '396'; t0: number; vehicles: number }[] }  // both segments; the page finds a chunk by t0

export interface StationsFile { v: 1; stations: { id: string; name: string; lon: number; lat: number; capacity: number | null }[] }
export interface BajsFile { v: 1; t0: number; step: 300; n: number; stations: string[]; bikes: string[] }   // bikes[i] = base64 of n uint8 for stations[i]: 0..250 bikes, 254 = not renting, 255 = missing

export interface ClosuresFile { v: 1;
  versions: { fromSec: number; toSec: number | null }[];                       // one per distinct copy of the dataset
  closures: { id: number; street: string; type: string; subtype: string | null; direction: string | null; line: [number, number][]; startSec: number | null }[];
  byVersion: [closureIdx: number, endSec: number | null][][] }                // per version: which closures, with the end as published in that copy (rolling ends stay visible)

export interface SnimkaEvent { id: string; atSec: number; kind: 'zet' | 'court' | 'return' | 'service' | 'recording'; title: string; text: string | null;
  sources: { label: string; url: string }[]; derived: boolean; chapter: boolean }   // derived = computed from the replayed series; chapter = a scrubber mark
export interface EventsFile { v: 1; events: SnimkaEvent[] }
export interface NoticesFile { v: 1; items: { id: number; title: string; text: string | null; link: string; pubSec: number }[] }
export interface NewsFile { v: 1; outlets: Record<'jutarnji' | 'vecernji' | 'n1', { name: string; home: string }>;
  items: { id: string; outlet: 'jutarnji' | 'vecernji' | 'n1'; title: string; link: string; pubSec: number; beat: string | null }[] }  // titles verbatim, no description

export type SentenceFamily = 'departure-timetable' | 'departure-live' | 'first-last' | 'service' | 'outage' | 'rail' | 'bikes' | 'closure' | 'event' | 'weather' | 'solar' | 'notice' | 'other';
export interface ScreenIndex { v: 1; runs: { id: string; kind: 'slot' | 'series' | 'return' | 'adhoc'; fromSec: number; toSec: number; readings: number;
  file: HashedRef; captures: { kiosk: HashedRef | null; phone: HashedRef | null };
  summary: { sentences: Partial<Record<SentenceFamily, number>>; departureRows: number; liveRows: number } }[] }
export interface ScreenRow { id: string; kind: string; source: string | null; live: boolean; title: string; whenText: string | null; sub: string | null; caveat: boolean }
export interface ScreenReading { at: number; sentence: string; kicker: string | null; kickerText: string | null; fact: string | null; family: SentenceFamily;
  rows: number[]; pills: string | null; mapNote: string | null; fleet: { pins: number | null; service: SnimkaState | null } | null }
export interface ScreenRun { v: 1; id: string; kind: ScreenIndex['runs'][number]['kind']; place: string; fromSec: number; toSec: number; rows: ScreenRow[]; readings: ScreenReading[] }   // one reading per 20 s
export interface BoardSeries { v: 1; stop: '106_1'; name: string; samples: { at: number; status: string; next: [routeId: string, headsign: string, atSec: number][] }[] }  // every 5 min, up to three departures at or after the sample, never padded
```

Codec (`shared/snimka-codec.ts`): `encodeMotionChunk`, `decodeMotionChunk(raw): MotionChunk` (validates), `samplesAt(chunk, tick): { id, route, label, kind, on, idx, s?, lon?, lat? }[]` (the positions at one tick, undelta'd), `encodeBajs`, `decodeBajs(file): Uint8Array[]`, `BAJS_NOT_RENTING = 254`, `BAJS_MISSING = 255`, `decodeManifest(raw): SnimkaManifest` (rejects a wrong version, a path with `..`, a hash that does not match its name), `contentName(name, ext, bytes): string`.

Byte budget: every motion chunk at most 150,000 bytes gzip (asserted by the pipeline); the window series about 50 KB gzip; the whole dataset about 20 MB on R2.

## 6. The pipeline (`scripts/snimka/`)

Offline, Node ESM, read-only against `review.local/`, output in `review.local/snimka/build/v1/{objects,work,state}`. `node scripts/snimka/build.mjs [--stage <name>|all] [--segment window|day] [--force]` bundles `scripts/snimka/main.ts` with esbuild the way `scripts/replay-twin.mjs` loads the replay core (`sharp` external). Each stage fingerprints its inputs and is skipped when they did not change.

- **One additive change to existing code:** `replayPublished(dirs, engine, { expect, routes, fromSec, toSec, onTick })` in `scripts/replay-core.ts`. It streams frames in header order (as `replayServiceDirectory` does), calls the real `runTick` with the engine and the expectation in one pass, feeds learned evidence back exactly as `replay()` does, and hands each tick's payload, service memory, `rejectedFuture`, `hidden` and entity count to the callback. Existing exports do not change.
- **frames:** the window runs on the 000396 artefacts in `app/public/data/` with an expectation index merged from 000396 and 000395 (`mergeExpectIndexes`, services namespaced, cut at 2026-09-28) so that early Monday is not "no calendar"; the comparison day runs on the 000395 artefacts in `test/fixtures/frames/2026-09-21-1715-1744/artefacts/` with `test/fixtures/frames/zet-expect-000395.json`. Only file names `HHMMSS-<epoch>.pb` are read. For each 10-second tick `T`, the latest payload with header at most 30 s before `T`; each published vehicle's plan is evaluated at `T` minus the header (`evalPathPlan`, `evalFreePlan`) and mapped to `on`/`idx` through the engine's own network. Only published vehicles are encoded; depot and parked vehicles are counted, never placed.
- **series, bajs, closures, screen:** as the contract says. The screen stage keeps every tenth reading, de-duplicates rows into the run's dictionary, assigns each reading a sentence family by its fact id (unknown is `other`; a departure sentence is `departure-live` when it counts down, "za N min" or "sada", else `departure-timetable`), and writes the board series of stop 106_1.
- **captures:** `sharp`, kiosk 1280 wide WebP quality 78, phone 540 wide. The pairing QR and the code line under it are located (`jsqr`) and blurred before encoding; a capture without a located code is logged and reviewed by eye.
- **news:** the three outlets' RSS, distinct by link. A pure, tested filter (`news-filter.ts`): relevance (strike or transport words and a Zagreb anchor, not a sport, world or crime category), near-duplicates within 6 h merged to the earliest, live blogs once, beats preferring their first report, at most 3 per hour and 10 minutes apart. It writes `work/news-candidates.json` for the owner's read-through. The published list is the committed `scripts/snimka/news-curated.json`; the build fails on a curated link that is not in the recordings.
- **events:** the committed `scripts/snimka/events.json` (Croatian, sourced; derived events carry a rule the stage resolves against the series). The chapter list is in §11.
- **manifest:** hashes and renames every object, copies both network artefacts, writes the attribution (§7 of `docs/izvori.md`), the notes and `upload-list.txt`.
- **verify:** the acceptance numbers of §10 rows SN-1 to SN-3, printed, exit 1 on a miss.
- **upload** (`scripts/snimka/upload.mjs`): `cf r2 objects put` into `vidikovac-feed` under `archive/strike-2026-09/public/v1/`, hashed objects first, the manifest last, then a size check of every key; `--local --subset dev` writes a small subset to the local R2 for `wrangler dev`.

## 7. The route

`worker/routes/snimka.ts`, registered in `ROUTES`: `GET` and `HEAD` under `/api/snimka/v1/` map to R2 `vidikovac-feed` (binding `RECORDINGS`) under the prefix `archive/strike-2026-09/public/v1/`. The prefix is outside the seven-day lifecycle rule, and a route that maps only `public/` can never reach the raw frames. A strict path rule (lowercase segments, `.json` or `.webp`, no `..`), the Cache API first (a hit costs no rate-limit budget), `openRateLimited` on a miss (429), 503 without the binding, 404 JSON never cached for a missing object, `access-control-allow-origin: *`, the data security headers, `public, max-age=31536000, immutable` for hashed objects and `public, max-age=60, s-maxage=300` for the manifest. No assets fallback.

## 8. The page

`/snimka/` follows `/statistika/`: a static Vite entry, `tokens.css`, `base.css`, `theme-init.ts`, the lightweight mode (`?lagano=1`), the theme controller, Manrope outside the lightweight mode, address state by `replaceState`, the scroll spy. It reuses `statistika.css` for the chrome, hero, number tiles, cards, tip and tables and adds its own sheets. It never calls a live API.

Sections: Ukratko (hero), Snimka (the stage), Zaslon, Tijek, Što se vidjelo, Izvori.

- **Hero:** eyebrow, title, two sentences of narration with their sources, four numbers computed from the series (hours in the replayed "gotovo bez vozila" state; vehicles at 07:45 on Monday against Thursday 24 September; bikes from the most to the fewest with empty stations; minutes from the first ten vehicles on Wednesday evening to the first "uobičajeno" minute).
- **The stage:** the map with a clock plate; play and pause, previous and next chapter, the speed control (a native select under 40rem), the layers (Vozila, Običan dan, BAJS, Zatvorene ulice), a native range scrubber over the 3,600 minutes with chapter ticks and day lines; a side column with the service state (word, counts, how long it has held, the "naknadno" mark before `serviceLiveFromSec`), "ZET javlja" (the latest notice), "Iz medija" (the latest curated headline within three hours, as a link) and "Događaj" (the latest event within an hour).
- **Zaslon:** a purpose-built miniature of the public screen (header sentence with its kicker, the "U blizini" rows) from the run that covers the minute; between runs the next timetable departures from Trg bana J. Jelačića with a note; the nearest capture within six hours; the quartet of 07:45 on four mornings.
- **Tijek:** six small multiples on one 60-hour axis with one cursor: vehicles in motion against the timetable (and the normal day when the overlay is on), the service state band (hatched where retroactive), bikes and empty stations, ZET's data (empty, not changing), the number the screen showed against vehicles with a position, press items per hour. Each has a table twin. Pointer seeks.
- **Što se vidjelo:** cards with numbers computed in the page by pure functions, each with a method line.
- **Izvori:** the manifest's attribution, the court source, the sentence that the strike is named only in this text, links to the dataset description, `/statistika/` and `/prijava/`.

The clock: `now() = clamp(anchor + (realNow - anchorReal) * speed)` while playing, re-anchored on every change, so it is deterministic for an injected real clock. A shared link (`?t=2026-09-28T07:45&brzina=600`, optional `&usporedba=1`) opens paused at its minute; reduced motion never autoplays and ticks once a second when played; a hidden tab freezes the clock. Keyboard on the stage: Space, J and L for chapters, comma and full stop for one minute (with Shift ten), 1 to 4 for the speeds.

The map: `createCityMap` keeps its own loop on real time. Two additive seams: `CityMapDeps.createModel?: (net) => Model`, through which the page supplies a stateless replay model whose `step()` returns the drawn vehicles for the replay clock (pills, labels and both palettes come from the map unchanged, and the integrator is not loaded), and `CityMapHandle.setGhosts?(points)`, one grey circle layer under the vehicles for the comparison day. Positions interpolate linearly along the path or shape between ten-second samples on the same geometry and snap on a geometry change, a missing neighbour or a hop over 400 m. BAJS and closures use the map's existing city points and lines with the wall's own marks. At 1 h/s no vehicles are drawn (the counts stay in the side column). A missing chunk shows "Bez snimke" and no vehicles, never a zero. The lightweight mode has no map and keeps everything else.

Budgets: the entry graph under 200,000 bytes gzip with no static reference to the map library, the fonts or the network file; the open-map graph under 620,000.

## 9. Rules for agents

- Croatian copy: standard and natural, gender-neutral for things, informal address, never "zid", never an em dash, a double hyphen or an ellipsis character, whole words. "štrajk" appears only in the page's narration and sources strings and in `events.json`, never in the product's catalogues or sentence files.
- Missing is never zero, in data and on screen.
- Never commit `review.local/`, `recordings/`, screen files or a recorded day; the fixture under `test/fixtures/snimka/` stays under 20,000 bytes and carries ZET's licence sentence.
- Never edit `app/prijava/` by hand; never change submitted text in `docs/prijava/`; the dated note goes in `docs/prijava/razvojne-biljeske.md` and the hosted page is rebuilt with `npm run build:prijava`.
- Never `wrangler deploy`, never push, never open production in a browser from a lane, never create a screen.
- Existing exports keep their signatures; the seams in shared map code are additive and leave the kiosk and the phone byte-for-byte on their current path.
