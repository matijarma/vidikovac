## Risks

- Probe-contract drift: the specs select on names (kiosk-place, nearby-row[data-kind], sada-sentence, share-city, session-ended, stop-board, data-unlabelled…) that WP1–WP4 implement in parallel; mitigated by test/accept/probes.test.ts naming the owning WP per probe and by keeping every selector in e2e/wall.ts, e2e/inventory.ts, e2e/legibility.ts (one place to rename).
- Fake clock vs the map: MapLibre and the motion loop run on rAF; `page.clock.runFor` advances timers but not real frames, so rotation samples wait 30 ms of real time after each step and map probes (`data-pills`) are read only after `data-map-status=ready`; e2e/round-f.spec.ts resumes the clock for camera work — the wall spec must not zoom under a stopped clock.
- `data-pills` on the wall map read null in headless production captures (analyse.mjs comment): WP2 must confirm the probe block of app/src/map/city-map.ts:1161-1230 runs for the kiosk container (`[data-testid=kiosk-map]`); until then the wall spec falls back to `data-bodies` > 0 and the '+N' check on the phone Karta.
- Workers AI is not available under `wrangler dev` with remoteBindings off: the sentence rows rely on WP1's template fallback; a spec that demanded model text would be untestable locally.
- Sample validity is tied to feed 000395: a regenerated trip index breaks joins (guard fails with a clear message); ZET recordings expire from R2 after 7 days, so the sample must be committed before 28 Sep from the local copy in review.local/companion/recordings.
- Repository weight: 157 × ~38 kB = 6.0 MB of binary `.pb` (≈ 1.6 MB in git packs); a 10-minute alternative (2.1 MB) loses statistical weight (42 → ~15 events). Decision recorded in expect.json; `.gitattributes` already marks `*.pb binary`.
- Legibility thresholds are standards-derived (DIN 1450 / Legge & Bigelow) and stricter than the DPR-0.25 proxy the research used (28 px read as legible); if WP1's row sub-lines land at 28 px the read-tier check fails by design — the tiers put sub-lines in walk-up; the owner may re-tier in P3 without code changes beyond WALL_1920.
- Accept-tier runtime: eight wall scenes × (load + 300 clock steps + proxy context) ≈ 8 × 60–90 s plus the phone spec; kept out of `npm run e2e`; `fullyParallel: false` and `workers: 1` remain (one shared local BeaconDO).
- The `accept` tier being red for weeks invites `test.skip`s; the fold-back rule (drop `--project` filters when all green) is written into both configs' comments and step 11's table so red rows stay visible, not skipped.
- `scripts/audit-production.mjs` behaviour change (refuse to create) alters the documented evaluator flow in its header comment; the header and docs/kiosk.md are updated in the same commit.
- `deviceScaleFactor: 0.25` contexts worked in the research (lib.mjs KIOSK_3M) with Chromium; the proxy capture is an artefact only, so a Playwright refusal degrades to a skipped screenshot, not a failure.
- Long-press detection (900 ms hold) and MutationObserver counts depend on WP1's exact implementation (pointer events vs touch, whether the sentence swap replaces a text node or an element); thresholds (≤ 2 mutations) are set for 'sentence swap only' and will need one adjustment pass when WP1 lands.
