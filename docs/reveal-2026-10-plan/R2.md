### 0.2 Seams inside the package (frozen)

Everything below is R2's own contract; the steps implement it exactly.

**The scheduler's constants** (`shared/kiosk/takt.ts`, exported, each with a one-line comment naming the brief §3 row):

| constant | value | meaning |
|---|---|---|
| `ADVANCE_EVERY_BEATS` | 4 | an advance may start on a beat `b` with `b % 4 === 0` |
| `PAGE_EVERY_BEATS` | 3 | a page turn may start on a beat `b` with `b % 3 === 0` |
| `REVEAL_GAP_BEATS` | 3 | a reveal starts only when the last one started at least 3 beats earlier (§0.5 item 1) |
| `PAGE_MAX_ROWS` | 2 | a page turn replaces at most 2 rows |
| `ADVANCE_LEAD_MS` | 600_000 | the first shown departure must be more than 10 min away |
| `REVEAL_IMMINENT_MS` | 1_800_000 | a row within 30 min of its moment is `imminent` and never replaced |
| `FRESH_MS` | 600_000 | freshness window (R0's, see 0.1); `shownAt` entries older than it are pruned |
| `REVEAL_EXEMPT_KINDS` | `['closure']` | never replaced and never revealed (§0.5 item 5) |

**`beatIndex(now, rhythmMs)`** = `Math.floor(now / rhythmMs)` for a finite `now` and a finite `rhythmMs > 0`, else `-1`. The beats are the absolute grid of the epoch (20, 30 and 60 s all divide a minute, so a beat index names the same instant on every wall).

**`takt(candidates, history, now, options)`**, rules in order (the reference implementation is in step 1):

1. `b = beatIndex(now, options.rhythmMs)`. `order(c)` = the index of the first candidate with that id (ties everywhere are broken by it, so the result never depends on sort stability). `listed` = the candidates whose kind is not `next-departures`; `next` = those whose kind is `next-departures`, in candidate order.
2. **Values.** `still(c) = candidateValue(c, now, null)` (the static value: freshness is uniform at 1.2, so the order is R0's value order, exactly the fitter's); `fresh(c) = candidateValue(c, now, history)`.
3. **Page 1** = every reserved `listed` candidate, then the non-reserved `listed` candidates by `still` descending (ties by `order`), cut so page 1 holds `max(capacity, number of reserved)` ids. `capacity` is `Math.floor(options.capacity)`, never below 0. `TaktResult.page1` lists the chosen ids **in candidate order** (the list's own order). A `next-departures` candidate is never on page 1. Freshness never changes page 1 (§0.5 item 8).
4. **Page 2** = the `listed` candidates not on page 1, not reserved, not of a kind in `REVEAL_EXEMPT_KINDS`, not of kind `departure` or `departures`, with `fresh(c) > 0`, ordered by `fresh` descending (ties by `order`).
5. **Quiet.** If `options.quiet`, or `b < 0`: no reveal.
6. **Gap.** A reveal may start only when `history.lastReveal === null` or `b − history.lastReveal.beat ≥ REVEAL_GAP_BEATS`. Otherwise no reveal. This is also how "the previous beat's reveal ends": the beat after a reveal can never carry one, so the rows return on it.
7. **Advance** when `b % ADVANCE_EVERY_BEATS === 0`, page 1 holds the `departures` candidate (it always does: it is reserved), its `atMs` is defined and `atMs − now > ADVANCE_LEAD_MS`, and `next.length > 0`: `{ kind: 'advance', ids: next.slice(0, 3) ids, replaces: ['departures'], beat: b }`.
8. **Page turn**, only when rule 7 gave none, when `b % PAGE_EVERY_BEATS === 0`: `out` = the page-1 candidates that are not reserved, not `imminent`, not of a kind in `REVEAL_EXEMPT_KINDS`, not of kind `departure` or `departures`, ordered by `still` ascending (ties: the later `order` first). `k = min(PAGE_MAX_ROWS, out.length, page2.length)`; when `k > 0`: `{ kind: 'page', ids: page2.slice(0, k) ids, replaces: out.slice(0, k) ids, beat: b }`; else no reveal.
9. At most one reveal per call (rules 7 and 8 are exclusive).
10. **History** (a new object; inputs are never mutated): `beat: b`; `shownAt` = the entries of `history.shownAt` with `0 ≤ now − at ≤ FRESH_MS`, then `shownAt[id] = now` for every page-1 id and every revealed id, keys sorted (a deterministic serialisation); `lastReveal` = `{ kind, beat: b }` of this call's reveal, else `history.lastReveal` unchanged.
11. `options.reduced` changes nothing in the result (D2: the same reveals, drawn as cuts); it is carried for the log and the renderer.

What this gives when both kinds are always eligible (12 beats): advance at 0, page at 3, 6, 9, advance at 12. When only advances are eligible (at night): beats 0, 4, 8 (one beat in four). When only page turns are eligible (by day, where the first departure is always within 10 min): 0, 3, 6, 9 (one beat in three).

**Candidates** (`app/src/kiosk/timeline.ts`, new export, pure):

```ts
export function taktCandidates(rows: readonly WallRow[], next: readonly NearbyRow[], now: number): TaktCandidate[];
```

- The `DeparturesLine` → `{ id: 'departures', kind: 'departures', atMs: line.atMs, reserved: true, imminent: line.atMs − now ≤ REVEAL_IMMINENT_MS }`.
- A `departure` row that `groupDepartures` left outside the line (a stray): `kind: 'departure'`, `reserved: true`.
- `notice`, `first`, `last`: `reserved: true` (the notice by the brief; first and last by decision 27, §0.5 item 4).
- The first timeless row in list order (`isTimeless`, the rule of `reservedRows`, `timeline.ts:178`): `reserved: true`; any later timeless row `reserved: false`.
- Every other row: `reserved: false`.
- `atMs` = `row.atMs ?? undefined`; `untilMs` = `row.untilMs` (set on cut and event rows, `nearby.ts:140`); `imminent` = `atMs !== undefined && atMs − now ≤ REVEAL_IMMINENT_MS` (a moment already past counts as imminent).
- `next` becomes candidates only when `next.length ≥ line.cells.length` (an advance never shows fewer cells than the line: the `departures` observer row reads "at least the fitted count"): each `{ id: row.id, kind: 'next-departures', atMs: row.atMs ?? undefined, reserved: false, imminent: false }`, in `next` order.
- Output order: the rows' order, then the `next` candidates.

### 0.3 Decisions applied

- **D2.** Reveals slide on beats: a page turn's rows enter with the existing 220 ms fade plus a translateY of one row height under the same `ENTER_MS`; the advance's cells fade in place. Reduced motion and lagano (`reducedMotion || lightweight`, the timeline's existing `reduced`, `invitation.ts:134`) get cuts: the same reveals, no `data-enter`, no `data-slide`. **At most one region moves per beat**: a reveal starts on beat `b` (one region moves), returns on `b + 1` (the same region), and nothing starts before `b + 3` (`REVEAL_GAP_BEATS`). The regions are the departures line and the list's rows; the map emphasis follows the revealed row and is part of its region; the header's turn is the beat itself (it turns on the rhythm today) and is not a second region.

### 0.5 Changes against the plan and the task text (with evidence)

1. **`REVEAL_GAP_BEATS = 3`.** The brief's two cadences (advance `b % 4`, page `b % 3`) start reveals on beats 0, 3, 4, 6, 8, 9 of every 12: six in twelve, with starts on consecutive beats (3 and 4, 8 and 9). That breaks both the brief's own observer rule (§6 DR2: "at most one reveal per 3 beats") and D2 (on beat 4 the list's rows return from beat 3 while the line advances: two regions). The gap rule keeps both cadences as eligibility and makes D2 and the observer rule hold; D2 wins over the numbers table (brief §0).
2. **`data-reveal` values** are `page:<beat>` and `advance:<beat>` (the task text), not the plan's `<kind>:<id>:<beat>`: the ids are in the rows themselves, and the beat is what the cadence rule reads.
3. **The beat budget is 6** (brief §3), not the plan's 4: a page turn of two rows is 4 records at its start and 4 at its return; the 6 leaves room for the line's label and a changed cell count, never for a rebuilt row.
4. **First and last trams are reserved** in `taktCandidates`, beside the line, the notice and one timeless row. Decision 27 (owner decisions 10 and 27, `timeline.ts:175-183` and `fitRows:190`) makes them promises the fitter never drops; a page turn hiding the last tram for a beat would break it. The brief's list of reserved rows did not name them; nothing in D2 asks for it.
5. **Closures are never replaced and never revealed** (`REVEAL_EXEMPT_KINDS`). The observer row `closure-reentries` (§16.3, `scripts/observe-production.mjs:1329`: "no closure row leaves the list and comes back") and the accept spec's "no closure re-entry" (`e2e/wall.ts:713`) would read every page turn over a closure as a failure, and a closure is a fact about now.
6. **The timeline's signature.** The task text writes `update(rows, { reveal })`; the handle is `update(rows, radiusM, now)` (`timeline.ts:102`, `:644`), called three times by `invitation.ts:199-207` and replayed by `refit` (`timeline.ts:772`). R2 adds `view?: TimelineView` as the fourth parameter; `next` travels with `reveal` because an advance draws rows the list does not hold.
7. **Where the beat lives.** `beatIndex(now, rhythmMs)` is frozen as a function of the clock, while the header turns relative to its own dwell (`createSentenceSequence`, `now − heldSince < rhythm`, `sentence.ts:563` and `:581`). So the beat is **the paint at which the sentence may turn**: the kiosk runs `takt` when `at ≥ max(sentenceSequence.turnAt(), beatAt + rhythmMs)` (while a reveal is on: when `at ≥ beatAt + rhythmMs`), and indexes it with `beatIndex(at, rhythmMs)`. Consecutive beats are at least a rhythm apart, so the index strictly increases; the reveal and the sentence that names it start on the same paint and last one rhythm. Where the header stands for minutes (nothing lasting: `sentence.ts:609-611`, the night), `beatAt + rhythmMs` keeps the beats coming, so night advances still happen. No dwell rule changes.
8. **Page 1 by the static value.** With `history` in page 1, a shown row reads ×1.0 and a page-2 row ×1.2, so page 1 would swap rows on every beat and disagree with the fitter (R0's `byValue` reads the static order). Page 1 uses `candidateValue(c, now, null)`; freshness ranks page 2 only, which is where it does its work (a row revealed in the last 10 min yields to one that was not).
9. **An advance names nothing in the header.** "A fact per revealed row" copies the row's own fact; the next departures have none (`sentenceFacts` says the first three departures only, `++departures > 3`, `sentence.ts:338`), and the line's "zatim" says it. A page turn names its rows.
10. **Quiet while the sentence is suspended** (`sentenceSuspended()`: a session label or the pairing notice holding the header). The sentence could not name the reveal, and the pairing notice is itself the beat's change.
11. **Quiet in the handheld composition.** A phone that opens `/kiosk/` gets an unbounded, scrolling list (`NEARBY_DESIGN_HEIGHT.handheld = ∞`, `invitation.ts:20-22`): page 1 only, as on the phone.
12. **Quiet while `capacity === 0`**: before the first paint the list's size is unknown.
13. **The emphasis for an advance stays the sentence's.** The next departures belong to the wall's own stop, already the map's subject; only a page turn moves the emphasis to its revealed row.
14. **Overlay on the painted rows.** `TaktCandidate` carries no "painted" flag (seam (a) is frozen), so when the measured fit dropped a tall row that `takt`'s page 1 holds, the two disagree. The timeline draws a page turn on what it painted: it removes the painted rows among `replaces` and inserts the unpainted rows among `ids`, pairwise, only while the list still fits whole (step 4). `takt`'s history keeps what it decided (it stays pure and replayable); the DOM's `data-reveal` says what was drawn.
15. **Ownership.** R2 also edits `app/src/kiosk/invitation.ts` (the model fields, `shown()`), `app/src/ui/kiosk-city.css` and `app/src/ui/kiosk.css` (the slide, the cut), `app/src/i18n/{hr,en}.json` (one key), `e2e/accept/wall.spec.ts` (the reveal scene), `test/app/kiosk.test.ts`, `test/scripts/observe-production.test.ts`. The brief §5.1 lists these under R1 or nobody for DR1; DR2 has one lane, so nothing is contended.

## Goal

The wall decides, on each beat of the header's rhythm, whether one region shows something more for exactly one beat: the departures line shows the next three departures under "zatim" (an advance), or the list swaps its one or two least valuable rows for the most valuable ones it had no room for (a page turn). The revealed row takes the map's emphasis and the header names it. Everything else stays put: the QR card, the safety strip, the header's structure, the reserved rows, the rows within 30 minutes of their moment, the closures. Nothing moves while a touch is open, in the paired phase or while ZET's state pins the header. The schedule is a pure function, replayed over a fixture day into a committed beat log, and the observer judges the cadence, the dwell and the motion budget in production.

export function beatIndex(now: number, rhythmMs: number): number {
  if (!Number.isFinite(now) || !Number.isFinite(rhythmMs) || rhythmMs <= 0) return -1;
  return Math.floor(now / rhythmMs);
}

const moves = (c: TaktCandidate): boolean =>
  !c.reserved && c.kind !== 'departure' && c.kind !== 'departures' && !REVEAL_EXEMPT_KINDS.includes(c.kind);

export function takt(candidates: readonly TaktCandidate[], history: TaktHistory, now: number, options: TaktOptions): TaktResult {
  const b = beatIndex(now, options.rhythmMs);
  const index = new Map<string, number>();
  candidates.forEach((c, i) => { if (!index.has(c.id)) index.set(c.id, i); });
  const order = (c: TaktCandidate): number => index.get(c.id)!;
  const still = (c: TaktCandidate): number => candidateValue(c, now, null);
  const fresh = (c: TaktCandidate): number => candidateValue(c, now, history);
  const listed = candidates.filter((c) => c.kind !== 'next-departures');
  const next = candidates.filter((c) => c.kind === 'next-departures');
  const reserved = listed.filter((c) => c.reserved);
  const rest = listed.filter((c) => !c.reserved).sort((x, y) => still(y) - still(x) || order(x) - order(y));
  const room = Math.max(0, Math.floor(Number.isFinite(options.capacity) ? options.capacity : 0) - reserved.length);
  const onPage1 = new Set([...reserved, ...rest.slice(0, room)].map((c) => c.id));
  const page1 = listed.filter((c) => onPage1.has(c.id)).map((c) => c.id);
  let reveal: TaktReveal | null = null;
  const gap = history.lastReveal === null || b - history.lastReveal.beat >= REVEAL_GAP_BEATS;
  if (!options.quiet && b >= 0 && gap) {
    const line = listed.find((c) => c.kind === 'departures' && onPage1.has(c.id));
    if (b % ADVANCE_EVERY_BEATS === 0 && line?.atMs !== undefined && line.atMs - now > ADVANCE_LEAD_MS && next.length > 0) {
      reveal = { kind: 'advance', ids: next.slice(0, 3).map((c) => c.id), replaces: [line.id], beat: b };
    } else if (b % PAGE_EVERY_BEATS === 0) {
      const page2 = listed.filter((c) => !onPage1.has(c.id) && moves(c) && fresh(c) > 0)
        .sort((x, y) => fresh(y) - fresh(x) || order(x) - order(y));
      const out = listed.filter((c) => onPage1.has(c.id) && moves(c) && !c.imminent)
        .sort((x, y) => still(x) - still(y) || order(y) - order(x));
      const k = Math.min(PAGE_MAX_ROWS, out.length, page2.length);
      if (k > 0) reveal = { kind: 'page', ids: page2.slice(0, k).map((c) => c.id), replaces: out.slice(0, k).map((c) => c.id), beat: b };
    }
  }
  const kept: Record<string, number> = {};
  for (const [id, at] of Object.entries(history.shownAt)) if (at <= now && now - at <= FRESH_MS) kept[id] = at;
  for (const id of [...page1, ...(reveal?.ids ?? [])]) kept[id] = now;
  const shownAt: Record<string, number> = {};
  for (const id of Object.keys(kept).sort()) shownAt[id] = kept[id]!;
  return { page1, reveal, history: { beat: b, shownAt, lastReveal: reveal ? { kind: reveal.kind, beat: b } : history.lastReveal } };
}
